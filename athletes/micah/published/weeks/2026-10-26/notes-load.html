The data behind this week

All seven days are full, from Steps 2026.10.02-2026.11.01 Health Connect.csv, the Source-carrying range export Health Sync wrote overnight into 11-02; the ISO-week file (Steps 44-2026) and the per-day files for the same dates carry no Source column and lose to it on precedence, so they changed nothing. The watch and phone counts were separated on every day, and run steps were summed inside each run's clock window with no alignment shift needed — the phone was back on Eastern time.

Sunday's sleep is published from a second source, and the readiness check turns on it. Runalyze returned two records for the night into 11-01: Garmin's at 6.78 h with a score of 77, and a second source: "API" record at 7.28 h with no score, whose duration is Garmin's plus the 30 awake minutes. The parser keeps the first record a payload lists, which here is the API one, so the 7.0 h floor passes; on Garmin's figure it would fail and Readiness would read 90 rather than 95. The same pair exists for 10-24 and 10-25, where both figures pass. Which source should win when both exist is an athlete decision not yet made; nothing in the parser prefers either.

The 10-25 resting HR correction (44 → 42) is upstream of this week too: it moved the 10-25 baseline's resting_hr_rise from +0.07 to −0.21, which is the figure the resting-hr-rise flag reads here.
