A note on how this week was graded

Two things about it were firsts, and both are recorded because they will recur.

The pace chart had to be rebuilt for a past week. Effective VO2max was 54.8 during this week against 55.8 today — a full point, worth about 6 sec/mi on every band. Grading against today's value would have judged these runs by a fitter athlete. The Runalyze API has no per-date endpoint for effective VO2max: get_calculations is current-only and takes no arguments, get_health_metrics does not carry it, and the per-activity effective_vo2max is a single-run estimate that swung 51.3 to 59.0 across this week alone — its mean, 56.1, is nowhere near the graph's 54.8. The value came off the athlete's own Running performance status graph. That is the only source, and grading any past week needs it.

Sunday forced the vocabulary to grow. A workout inside a longer continuous run had no representation: one role had to describe the whole activity, so Sunday was either a long run that scored 25% for correct execution, or a progression with no long run in the week and 0% quality time. Both were wrong, and the second contradicted the block history, which credited that same session 1,649 seconds. quality_splits and is_long now let the prescription name the block and the long run separately from the role that grades it.
